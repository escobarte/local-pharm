# CLAUDE.md — Local Pharm

Домашний учёт лекарств: что есть, где лежит, когда истекает. PWA для двух пользователей с общей базой.

## Роли

- **Владелец** — решения, git (commit / push), деплой на Vercel, проверка на проде.
- **Штаб (Claude Chat)** — планирование, промпты, обновление `docs/STATE.md`.
- **Claude Code (ты)** — код, миграции, тесты, документация в репозитории.

## Что читать в начале сессии

| Файл | Зачем |
|---|---|
| `CLAUDE.md` | Правила (этот файл) |
| `docs/STATE.md` | Где мы и что дальше. **Только чтение** |
| `docs/PLAN.md` | Фазы и критерии приёмки |
| `docs/GOTCHAS.md` | Известные грабли |
| `docs/BRAND.md` | Цвета, шрифты, токены |
| `docs/WIREFRAMES.md`, `docs/mockups/` | Экраны и их состав |

## Жёсткие правила

1. **Git не трогать.** Никаких `git add`, `commit`, `push`, `merge`, `checkout`, смены веток. Только чтение (`git status`, `git diff`, `git log`).
2. **`docs/STATE.md` не редактировать.** Его ведёт штаб, сохраняет владелец.
3. **Нет локального запуска у владельца.** Проверка: `tsc`, `lint`, `build` в твоём окружении, дальше владелец смотрит Vercel-деплой.
4. **Секреты не в репозиторий.** В коде и доках только имена переменных. `.env*` в `.gitignore`, пример в `.env.example`.
5. **Дизайн только через токены** из `docs/BRAND.md`. Никаких «лишних» цветов в компонентах.
6. **Продуктовых решений не принимать.** Развилка или конфликт требований — остановиться и задать один вопрос с вариантами.
7. **Задача из другой области** — записать в отчёт в «хвосты», не делать.
8. **Версии зафиксированы.** Точные версии в `package.json`, `packageManager` и `engines.node` указаны. Никаких `latest`.

## Стек

| Слой | Технология |
|---|---|
| Фреймворк | Next.js (App Router), TypeScript strict |
| Стили | Tailwind CSS, токены из `docs/BRAND.md` |
| Хостинг | Vercel (Hobby), домен `*.vercel.app` |
| БД / Auth / файлы | Supabase: PostgreSQL, Auth (Google), Storage |
| Supabase в Next.js | `@supabase/ssr` |
| Миграции | SQL-файлы в `supabase/migrations/` |
| Фоновые задачи | Vercel Cron |
| PWA | Web App Manifest + service worker |

## Конвенции

- Язык интерфейса: русский. Код, имена, комментарии: английский.
- Структура: `app/` (маршруты), `components/`, `lib/` (supabase, утилиты), `supabase/migrations/`.
- Мобильная ширина в приоритете (390 px), touch-цели не меньше 44 px.
- Доступность: настоящие `<button>`, `<a>`, `<label>`; контраст текста ≥ 4.5:1.
- Переменные окружения: `NEXT_PUBLIC_*` зашиваются при сборке — после изменения нужен Redeploy (не просто Restart).

## Ритуал завершения (каждая задача)

1. Прогнать `tsc`, `lint`, `build` (и тесты, если есть).
2. Новая запись сверху в `docs/CHANGELOG.md`.
3. Обновить `docs/PLAN.md`, если изменились критерии или нумерация.
4. Новые грабли — в `docs/GOTCHAS.md`.
5. Напомнить владельцу обновить `docs/STATE.md`.
6. Отчёт: изменённые файлы, как проверить на Vercel, риски, хвосты.
7. **Не коммитить.**

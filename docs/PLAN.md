# PLAN — Local Pharm

Фазы по порядку. Фаза закрыта, когда выполнены все критерии приёмки и владелец проверил на Vercel с телефона.

## Фаза 0 — Каркас и деплой

- Next.js + TypeScript strict + Tailwind, зафиксированные версии.
- Токены из `docs/BRAND.md` в конфиге Tailwind / CSS-переменных.
- Web App Manifest (название, цвета, иконки-заглушки 192/512), `viewport`, `theme-color`.
- Одна страница-заглушка «Local Pharm» в палитре.
- `.env.example` (пока пустой список переменных с комментариями), `.gitignore`.

Приёмка:
- [ ] `tsc`, `lint`, `build` без ошибок.
- [ ] Vercel собирает проект из репозитория.
- [ ] Страница открывается на телефоне, «Добавить на главный экран» ставит приложение с иконкой и названием.

## Фаза 1 — Основа: вход, БД, защита

- Миграции: таблицы `locations`, `boxes`, `compartments`, `categories`, `medications`, `packs`, `allowed_emails`.
- RLS на всех таблицах: доступ только для пользователей из `allowed_emails`.
- Вход через Google (Supabase Auth), экран «Вход» по `docs/mockups/Main-v3.dc.html`.
- Чужой аккаунт Google получает понятный отказ.
- Защищённые маршруты: без входа — редирект на «Вход».
- Vercel Cron раз в сутки: лёгкий запрос к БД (keep-alive).

Приёмка:
- [ ] Оба email из белого списка входят и видят одни и те же данные.
- [ ] Третий аккаунт получает отказ, данных не видит (проверка и в UI, и прямым запросом к API Supabase).
- [ ] Cron виден в Vercel и отрабатывает.

## Фаза 2 — Хранение

- Экраны «Хранение» и «Коробка» (схема отсеков).
- Создание/редактирование зон, коробок, отсеков.
- Ручное добавление препарата и упаковки (режим «Вручную» экрана «Добавление»).
- Нижнее меню (5 пунктов, «+» по центру).

Приёмка:
- [ ] Можно завести коробку с отсеками и положить в отсек упаковку.
- [ ] Упаковка видна в коробке, с количеством и сроком.

## Фаза 3 — Поиск

- Главная (поиск, «Внимание», категории), «Результаты», «Карточка препарата».
- Поиск по названию, веществу, категории; в результате всегда место и срок.
- Действия «Взял 1 шт.», «Заканчивается».

Приёмка:
- [ ] Поиск находит по названию и по действующему веществу.
- [ ] Из результата видно место хранения без лишних переходов.

## Фаза 4 — Справочники и сканер

- Разведка: формат и доступ к реестру AMDM (сначала отчёт, потом код).
- Импорт AMDM в свою таблицу; openFDA / RxNorm как запасной поиск.
- Сканер штрихкода камерой; штрихкод сохраняется в `medications.barcode`.

Приёмка:
- [ ] Повторный скан той же упаковки находит препарат из своей базы.
- [ ] Поиск показывает источник записи.

## Фаза 5 — QR-наклейки

- QR на коробку ведёт на её страницу; печать листа наклеек.

## Фаза 6 — Сроки и покупки

- Экраны «Сроки годности» и «Покупки».
- Еженедельное письмо: что истекает за 30 дней.

## Фаза 7 — PWA

- Офлайн-режим (кэш данных для поиска), push-уведомления (iOS — только с главного экрана).

## Фаза 8 — Надёжность

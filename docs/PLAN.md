# PLAN — Local Pharm

Фазы по порядку. Фаза закрыта, когда выполнены все критерии приёмки и владелец проверил на Vercel с телефона.

## Фаза 0 — Каркас и деплой

- Next.js + TypeScript strict + Tailwind, зафиксированные версии.
- Токены из `docs/BRAND.md` в конфиге Tailwind / CSS-переменных.
- Web App Manifest (название, цвета, иконки-заглушки 192/512), `viewport`, `theme-color`.
- Одна страница-заглушка «Local Pharm» в палитре.
- `.env.example` (пока пустой список переменных с комментариями), `.gitignore`.

Приёмка:
- [ ] `tsc`, `lint`, `build` без ошибок.
- [ ] Vercel собирает проект из репозитория.
- [ ] Страница открывается на телефоне, «Добавить на главный экран» ставит приложение с иконкой и названием.

## Фаза 1 — Основа: вход, БД, защита

- Миграции: таблицы `locations`, `boxes`, `compartments`, `categories`, `medications`, `packs`, `allowed_emails`.
- RLS на всех таблицах: доступ только для пользователей из `allowed_emails`.
- Вход через Google (Supabase Auth), экран «Вход» по `docs/mockups/Main-v3.dc.html`.
- Чужой аккаунт Google получает понятный отказ.
- Защищённые маршруты: без входа — редирект на «Вход».
- Vercel Cron раз в сутки: лёгкий запрос к БД (keep-alive).

Приёмка:
- [ ] Оба email из белого списка входят и видят одни и те же данные.
- [ ] Третий аккаунт получает отказ, данных не видит (проверка и в UI, и прямым запросом к API Supabase).
- [ ] Cron виден в Vercel и отрабатывает.

## Фаза 4 — Справочники и сканер

Делится на две части.

### 4a — Реестр AMDM

- Импорт выгрузки AMDM (`.xls`) в свою таблицу `amdm_registry` (миграция 0004, скрипт `scripts/amdm/`, данные не в репозитории).
- «Добавление» → «Поиск»: поиск по реестру на сервере (название, вещество, ATC, штрихкод; кириллица через транслитерацию), до 30 результатов.
- Выбор результата заполняет форму, сохранение с `source = 'amdm'`, `registry_code`, штрихкодом из реестра.
- Источник записи тегом в карточке и в результатах поиска.

Приёмка:
- [ ] Реестр загружен в Supabase: 6331 строка, коды с ведущими нулями.
- [ ] Поиск находит препарат по латинскому названию, по-русски и по штрихкоду из реестра.
- [ ] Препарат из реестра сохраняется с источником «Реестр AMDM» и штрихкодом; ручной режим работает как раньше.
- [ ] Поиск показывает источник записи.

### 4b — Сканер, своя база, openFDA, дубли

- Сканер штрихкода камерой (нативный `BarcodeDetector` или ZXing, лениво) и ручной ввод штрихкода; штрихкод сохраняется в `medications.barcode` при любом способе добавления.
- Порядок по штрихкоду: своя база → реестр AMDM → «Не нашли» и поиск по названию с запомненным штрихкодом.
- Вкладка «Поиск» тремя блоками: «У вас дома», «Реестр Молдовы», «Международные базы» (openFDA). RxNorm не подключаем.
- Защита от дублей: «Добавить упаковку к существующему» вместо новой записи.

Приёмка:
- [ ] Повторный скан той же упаковки находит препарат из своей базы.
- [ ] Скан на iPhone (Safari) и Android распознаёт EAN-13 с реальной упаковки.
- [ ] Отказ в камере и нет камеры — понятный текст и ручной ввод.
- [ ] openFDA недоступен — остальные блоки поиска работают.
- [ ] Выбор из реестра или скан штрихкода, который уже есть дома, предлагает добавить упаковку, а не создаёт дубль.

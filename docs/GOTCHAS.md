# GOTCHAS — Local Pharm

Формат: **Симптом/ловушка** — почему так и как правильно. Файл или место.

## Схема / БД

- **Supabase Free засыпает после 7 дней без активности** — проект останавливается, вернуть можно только вручную из панели. Нужен ежедневный Vercel Cron с запросом к БД.
- **Supabase Free без бэкапов** — нужен экспорт JSON из приложения и регулярная выгрузка.
- **Лимиты Free: 500 MB БД, 1 GB файлов** — фото упаковок сжимать перед загрузкой.
- **«Grant API access to new tables automatically» выключено** — новая таблица отвечает `permission denied` (42501) даже с RLS-политиками, пока в миграции нет явного `GRANT ... TO authenticated`. Каждая новая таблица: `enable row level security` + политика + `GRANT`.
- **RLS не действует на `TRUNCATE`** — ролям API выдавать только `select, insert, update, delete`, никогда `all`. В миграции сначала `revoke all`, потом точечный `grant`. `supabase/migrations/0001_init.sql`.
- **Postgres по умолчанию даёт `EXECUTE` на функции роли `PUBLIC`** — для каждой функции `revoke all ... from public, anon, authenticated`, затем явный `grant execute`.
- **`security definer` функции — только с `set search_path = ''`** и полными именами `public.x`, иначе подмена объектов через search_path.

## Авторизация

- **По умолчанию войти может любой аккаунт Google** — белый список + RLS на уровне БД, а не только проверка в UI.
- **`user_metadata` в JWT редактирует сам пользователь** — в RLS и `is_allowed()` опираться только на `email` и `app_metadata`. Провайдер проверяется через `app_metadata.provider`, иначе при включённом входе по почте можно зарегистрироваться с чужим email.
- **Server Components не могут менять cookies** — `signOut()` там молча не сработает. Выход только в Server Action или Route Handler (`app/(app)/actions.ts`, `app/auth/denied/route.ts`).
- **Next.js 16: `middleware.ts` переименован в `proxy.ts`** — proxy только для быстрой проверки сессии; белый список проверяется в `app/(app)/layout.tsx` и `/auth/callback`.
- **Preview-домены Vercel не входят в Redirect URLs Supabase** — вход на preview-деплое вернёт на Site URL. Проверять вход на production-домене.

## Окружение / деплой

- **`NEXT_PUBLIC_*` зашиваются при сборке** — после изменения нужен Redeploy в Vercel.
- **Vercel Hobby — только некоммерческое использование.**
- **Vercel Cron на Hobby — не чаще раза в сутки, время срабатывания плавает в пределах часа**; расписание в UTC. Vercel сам шлёт `Authorization: Bearer $CRON_SECRET`, если переменная задана.
- **Версия Node на Vercel берётся из `engines.node` / настроек проекта** — в Project Settings → Node.js Version должна стоять 22.x, иначе сборка пойдёт на другой версии.

## Next.js / React

- **React 19 сбрасывает форму после Server Action — даже если действие вернуло ошибку.** Неконтролируемые поля вернутся к `defaultValue`. Решение: действие возвращает `values`, форма берёт `defaultValue={state.values?.x ?? initial.x}` (`lib/storage/action-state.ts`, `components/BoxForm.tsx`).
- **Страница, которая читает данные только при наличии env, пререндерится на сборке** и падает без переменных. `cookies()` вызывается первым в `createSupabaseServerClient`, тогда все экраны динамические (`lib/supabase/server.ts`).
- **Server Action нельзя считать защищённым маршрутом.** Proxy его может не покрывать — в каждом действии заново проверяется доступ (`requireClient` в `lib/storage/actions.ts`), плюс RLS.
- **Tailwind: `w-full` и `w-auto` в одной строке классов — побеждает тот, что позже в CSS, а не в строке.** Общие классы кнопок не содержат ширины; в колонке они растягиваются сами (`components/ui.ts`).
- **`useFormStatus` работает только в дочернем компоненте формы**, поэтому кнопка отправки вынесена в `components/SubmitButton.tsx`.

## Хранение

- **`packs` → `compartments` и `packs` → `medications` — `ON DELETE RESTRICT`.** Коробку или отсек с упаковками удалить нельзя (код 23503); в интерфейсе это «В отсеке/коробке есть упаковки». Чтобы опустошить отсек, упаковки удаляют или перекладывают на карточке препарата (`/medications/[id]`), после этого отсек и коробку можно удалить.
- **Препарат и упаковка создаются одной RPC `add_medication_with_pack`.** Два отдельных запроса с клиента оставляют препарат-сироту при сбое второго.
- **RPC с правами вызывающего (`SECURITY INVOKER`) подчиняется RLS** — чужой аккаунт получает ошибку RLS, а не данные. Не менять на `SECURITY DEFINER` без явной проверки `is_allowed()`.
- **Срок годности на упаковке — «до конца месяца».** `12/2026` сохраняется как `2026-12-31` (`lib/dates.ts`).

## Реестр AMDM (Фаза 4a)

- **Данные реестра не попадают в публичный репозиторий.** Выгрузка, CSV и SQL лежат в `data-tmp/` (в `.gitignore`). Правило `.gitignore` не убирает уже закоммиченный файл: его снимают с учёта `git rm --cached`, а из истории — только переписыванием истории.
- **Нормализация одна на двоих: `lib/amdm/normalize.ts`.** Скрипт импорта строит ею `search_text`, приложение — слова запроса. Изменили функцию → пересобрать CSV и перезалить реестр (`docs/SETUP-SUPABASE.md`, 7.4), иначе запросы и данные разойдутся. Поэтому скрипт двухшаговый: Python только читает `.xls` (xlrd), очистка и `search_text` — в TypeScript (`scripts/amdm/`).
- **Выход нормализации — только `[a-z0-9 ]`.** Поэтому слова запроса можно вставлять в фильтр PostgREST (`or=(search_text.like.*x*)`) без экранирования. Если когда-нибудь разрешить в выходе точку, запятую, скобки или `*` — фильтр сломается или станет инъекцией.
- **Дефисы и апострофы склеивают, а не разделяют:** «No-spa» → `nospa`, «Hoffmann-La» → `hoffmannla`. Запрос «но-шпа», «ношпа» и «no spa» находят No-spa.
- **Код препарата — `text`, не число:** у 1796 кодов ведущий ноль. У 5 строк код из 7 цифр, а не из 10. `rx` — `boolean` (RX = true, OTC = false).
- **Штрихкод есть у 258 строк из 6331** (ещё у 91 стоит «0», это пусто). Один штрихкод бывает у нескольких кодов (133 строки) — поиск по штрихкоду показывает все. Длины 13, 12 и 8; для 12 цифр (UPC-A) ищется и вариант с ведущим 0, для 13 с нулём — без него.
- **Одна торговая марка — много строк** (каждая фасовка и дозировка — свой код): «paracetamol» находит больше 30. Сервер берёт до 300 строк по алфавиту, ранжирует в Node (название начинается с запроса → содержит → совпало по веществу/ATC) и показывает 30. При очень коротких запросах лучшие совпадения могут не попасть в эти 300.
- **Транслитерация кириллицы — best effort** (`lib/amdm/translit.ts`). Каждое слово даёт до 8 латинских вариантов (к → c/k, ц → c/ts/z, х → h/ch/c, г → g/h, ш → sh/s, двойные согласные → двойная/одинарная), слово совпадает, если совпал любой вариант. Не найдёт: русские названия, которые не транслитерация латинского («Активированный уголь» = Carbo activatus, «Зелёнка»), русские бренды, которых нет в реестре Молдовы, и редкие написания, не попавшие в 8 вариантов. Кириллица в самом реестре почти отсутствует (21 буква-двойник в именах фирм), поэтому искать по-русски можно только через транслитерацию.
- **`"abc".includes("")` — это `true`.** На конце слова «следующая буква» пустая; без проверки `ch !== ""` конечное «к» в «диклофенак» считалось стоящим перед мягкой гласной (вышло `diclofenak`).
- **Категория по ATC — только где первая буква однозначна** (`lib/amdm/atc-category.ts`): сейчас только C → «Давление и сердце». Остальные буквы смешивают несколько домашних категорий (N — и обезболивающие, и снотворные; R — и простуда, и аллергия), их выбирает пользователь.
- **Сохранение из реестра — своя RPC `add_registry_medication_with_pack`.** `source = 'amdm'`, `registry_code` и `barcode` функция берёт из строки реестра сама; с клиента приходит только код. Подделанный или исчезнувший код → `P0002` → «Препарат не найден в реестре AMDM». Функция ручного режима из 0002 не менялась.
- **React сбрасывает форму после ошибки** — скрытое поле `registryCode` стоит с `value` из пропсов, поэтому после сброса снова содержит выбранный код (как и требуется). Прочие поля берут `state.values` → предзаполнение → пусто. Форма при выборе другой строки реестра пересоздаётся (`key = registryCode`), иначе `defaultValue` не обновился бы.
- **`pg_trgm` в Supabase живёт в схеме `extensions`.** Миграция находит схему расширения сама и строит индекс с `<схема>.gin_trgm_ops`, а не надеется на `search_path`.
- **CSV-импорт в Table Editor мог бы записать пустые строки вместо NULL.** После импорта — проверочный запрос из `docs/SETUP-SUPABASE.md` (7.2). Приложение пустую строку и NULL показывает одинаково.
- **В тестах Next.js `[role=alert]` совпадает с невидимым анонсером маршрутов** (`next-route-announcer`). Ждать конкретный элемент: `p[role=alert]` или текст.

## Поиск и действия с упаковкой

- **Поиск по тексту делается в коде, а не в SQL** (`lib/medications/search.ts`). `ilike`/`lower()` в Postgres зависят от локали базы и могут не сворачивать регистр кириллицы; список лекарств небольшой, поэтому каталог читается одним запросом и фильтруется в Node. `ё` приравнивается к `е`. Слова запроса ищутся в любом порядке (все должны встретиться).
- **PostgREST отдаёт не больше 1000 строк за запрос** (лимит Supabase по умолчанию). Каталог препаратов и список упаковок для счётчиков читаются без пагинации: если упаковок станет больше тысячи, счётчики и поиск начнут занижать результат — тогда нужна пагинация или серверный поиск.
- **«Взял 1 шт.» — один `UPDATE` в функции `take_one_from_pack` (миграция 0003), а не «прочитал → записал»**: иначе два человека, нажавшие одновременно, затирают друг друга. Количество не уходит ниже 0; при 0 функция возвращает пустой результат, интерфейс показывает «уже ничего не осталось».
- **«Заканчивается» отправляет явное новое значение (`true`/`false`), а не «переключить»** — двойной тап или устаревшая страница не переворачивают флаг обратно.
- **В одной странице несколько `<dialog>`**: `aria-labelledby` с фиксированным id ломается (дубли id). `ConfirmDialog` берёт id из `useId()`.
- **Закрытый `<dialog>` остаётся в DOM** — в тестах и проверках размеров отсекать элементы с нулевой шириной, а локаторы по тексту делать точными (`exact`).
- **Сортировка результатов — по самой срочной упаковке препарата**: просроченные, затем истекающие в 30 дней, затем остальные по названию. Одна карточка = один препарат (количество суммируется, место берётся у самой срочной упаковки).

## Десктоп (адаптив, Фаза 3b)

- **Точка переключения `lg` (1024 px) живёт в двух местах**: в классах `lg:` и в `DESKTOP_QUERY` внутри `components/DesktopSelectLink.tsx` (там `matchMedia`). Менять только вместе.
- **Master-detail: клик на карточке или плитке на десктопе перехватывается в браузере** (`DesktopSelectLink`): `router.replace(?selected=… / ?box=…)`. Настоящий `href` остаётся мобильным (`/medications/[id]`, `/storage/[boxId]`) — по нему идут мобильная версия, Ctrl/⌘-клик, QR и случай «JS ещё не загрузился». Выбранный элемент подсвечивается через `data-selected`, а не `aria-current`: на мобильной версии подсветки нет, и «текущий» там был бы ложью.
- **Панель справа в DOM есть и на мобильной ширине** (`hidden`, `display: none`): сервер читает данные выбранного препарата/коробки и для телефона. Дубли текста в DOM (например, блок «Показания» на карточке препарата рендерится дважды, один скрыт) — в тестах и проверках брать только видимые элементы.
- **Server Actions упаковки (`deletePack`, `movePack`, `createPack`) после успеха делают `redirect('/medications/[id]')`**: из панели поиска пользователь попадает на полную карточку, а не остаётся в списке. Логику действий не меняли (договорённость Фазы 3b); если нужно «остаться в панели», действиям надо принимать адрес возврата.
- **`<Page>` обязан оставаться `flex flex-1 flex-col`**: на мобильных формах липкая панель «Сохранить» (`sticky bottom-0`) держится на том, что форма растягивается на всю высоту экрана. Без `flex-1` панель «съезжает» под содержимое.
- **Показать/скрыть по ширине: `hidden lg:flex` или `flex lg:hidden`.** Нельзя ставить `hidden` в одну строку с общими классами кнопок (`primaryButtonClass`, `secondaryButtonClass` и др. уже содержат `flex`): победит то, что позже в CSS, а не в строке (см. запись про `w-full`/`w-auto`). В таких случаях элемент оборачивают в `<div className="hidden lg:flex">`.
- **Проверять мобильную версию надо пиксельным сравнением с `HEAD`**, а не «на глаз»: на Фазе 3b сборка из `git archive HEAD` и сборка с правками сняты на 390 и 768 px по 18 экранам, расхождение — 0 px.


## Сканер, штрихкоды, openFDA (Фаза 4b)

- **Штрихкод хранится в одном виде:** EAN-13 или EAN-8 после `parseBarcode` (`lib/barcode.ts`); UPC-A (12 цифр) — это EAN-13 с ведущим 0 и сохраняется как 13 цифр. Поиск по базе и реестру всё равно пробует обе записи (`barcodeLookupVariants`): в 4a штрихкоды из реестра сохранялись как есть, в реестре есть 12-значные.
- **В реестре 6 штрихкодов из 258 с неверной контрольной цифрой** (Diazolin, Sulfacil, Lerkamen® 10). В форму они не подставляются (форма бы не сохранилась), на карточке выбранной строки — пометка «штрихкод с ошибкой».
- **`BarcodeDetector` есть не везде:** нет в iOS Safari, Firefox и Chrome на Linux/Windows. Тогда работает ZXing (`@zxing/browser` 0.2.1 + `@zxing/library` 0.23.0, ~456 КБ). Он грузится через `import()` только на вкладке «Скан» — в общий бандл не попадает (проверено по сетевым запросам).
- **Камера только в безопасном контексте:** https или `localhost`. По `http://IP` в локальной сети `navigator.mediaDevices` нет вовсе — показываем «работает только на защищённом адресе».
- **Камеру надо гасить самим:** при уходе со вкладки (размонтирование), при скрытии страницы (`visibilitychange`) и сразу после распознавания — `track.stop()` для всех дорожек. Иначе на телефоне горит индикатор камеры и садится батарея.
- **В headless Chromium без устройств ошибка «нет камеры» приходит раньше «нет разрешения»:** чтобы проверить отказ, нужен `--use-fake-device-for-media-stream` без выданного разрешения. Фейковое видео — Y4M-файл с нарисованным EAN-13 (`--use-file-for-fake-video-capture`).
- **openFDA — только с сервера,** 5 с таймаут (`AbortSignal.timeout`), без ключа. Лимит без ключа — 240 запросов в минуту и 1000 в сутки **на IP**; у Vercel общие исходящие IP, поэтому «недоступны» (429) возможно и без нашей вины. Кэш Next.js не используется (`no-store`), чтобы не закэшировать ошибку на сутки.
- **openFDA отвечает 404 на «ничего не найдено»** (`{"error":{"code":"NOT_FOUND"}}`) — это пустой результат, а не сбой.
- **В label API нет полей «форма» и «сила».** Форма берётся из хвоста `openfda.generic_name` («…TABLET, FILM COATED»), иначе из текстов этикетки; сила — регуляркой из «Active ingredient» / «Dosage forms and strengths». Best effort, пользователь правит перед сохранением.
- **Блок openFDA в `<Suspense>`:** страница отдаёт «У вас дома» и «Реестр» сразу (стриминг), международный блок догружается. Медленный openFDA не задерживает остальное.
- **Названия в openFDA — американские:** paracetamol там acetaminophen, salbutamol — albuterol. В запрос добавляется маленькая таблица таких замен (`lib/openfda/query.ts`). Местные UPC/EAN в openFDA почти не встречаются: поиск по штрихкоду там полезен только для американских упаковок.
- **Выбор строки openFDA передаётся в URL** (`fn`, `fi`, `ff`, `fs`, `fm`), без второго запроса к API. Сервер чистит эти значения так же, как поля ручной формы, и `source = 'openfda'` — только подпись: доверия к ним не больше, чем к ручному вводу.
- **Защита от дублей — дважды:** при выборе строки (страница проверяет `registry_code` и штрихкод) и при сохранении (Server Action проверяет снова, если в форме нет `allowDuplicate=1`). «Создать отдельную запись» в форме — вторая кнопка отправки с `name="allowDuplicate" value="1"`.
- **Запрос дублей `or=(registry_code.eq.X,barcode.in.(…))`** собирается только из цифр (`duplicateFilter`), иначе фильтр PostgREST можно было бы подменить.

## QR-наклейки (Фаза 5)

- **В QR зашит домен:** `<origin>/q/<qr_token>`. Сменится адрес приложения (другой проект Vercel, свой домен) — старые наклейки поведут на старый адрес. Адрес берётся с той страницы, откуда печатают, или из `NEXT_PUBLIC_SITE_URL`; печатать стоит с основного production-адреса, не с preview-деплоя. `qr_token` не меняется при редактировании коробки, поэтому перепечатка нужна только при смене домена.
- **Сканер в приложении открывает только свои наклейки:** `parseBoxQr` (`lib/qr.ts`) принимает адрес своего origin (текущий + `NEXT_PUBLIC_SITE_URL`) с путём ровно `/q/<uuid>`, либо сам токен. Чужой QR — «Это не наклейка Local Pharm», переход на чужой адрес не делается никогда. Наклейки, напечатанные со старого домена, сканер приложения тоже не примет (камера телефона откроет их на старом адресе).
- **`/q/<token>` не различает «нет такой коробки», «испорченный токен» и «не ваша коробка» (RLS)** — везде «Коробка не найдена», ответ 404, токен на странице не выводится.
- **Возврат после входа — через `?next=`:** proxy сам ставит `next` для любого закрытого адреса, `/login` → кнопка Google → `/auth/callback?next=…` → туда же. Каждая точка пропускает `next` через `safeNextPath` (`lib/routes.ts`): только «/…», без `//`, без обратной косой черты где угодно, без управляющих символов, до 1024 символов. Если вход уже есть, `/login?next=…` сразу ведёт по `next`.
- **Redirect URL в Supabase должен пропускать `?next=`:** в `redirectTo` уходит `/auth/callback?next=/q/…`. В Redirect URLs стоит маска `https://<домен>/**` (`docs/SETUP-SUPABASE.md`, шаг 3) — с ней адрес с параметром проходит. Если заменить маску точным `…/auth/callback`, Supabase может не принять адрес с параметром и вернуть на Site URL без `next`.
- **Печать: один и тот же DOM для предпросмотра и бумаги.** Все размеры листа — в `cqw` контейнера-листа (`mmToCqw` в `lib/labels.ts`): на экране лист шириной колонки, в печати ровно 210 × 297 мм, поэтому 1 мм раскладки = 1 мм на бумаге. `@page { size: A4; margin: 0 }` задаётся только на странице печати; поля листа — внутри раскладки.
- **В печати медиазапросы считаются по ширине бумаги (~794 px), а не окна:** десктопные `lg:` классы на бумаге не действуют. Поэтому у `(form)/layout.tsx` есть `print:max-w-none` (иначе мобильная колонка `max-w-md` обрежет лист), а меню (`SideNav`, `BottomNav`) и элементы управления — `print:hidden`.
- **Браузер печатает фон только с галочкой «Фон»:** QR — это SVG-`path` (печатается всегда), а не фоновый цвет. Пунктир по контуру наклейки — `border` цвета `border`, он печатается и помогает резать обычную бумагу.
- **Масштаб в окне печати должен быть 100 %:** «По размеру страницы» уменьшит лист, и сетка не совпадёт с листом наклеек. Подсказка об этом стоит на странице печати.
- **Сетки листов — Avery L7166 (6 шт., 99,1 × 93,1 мм) и L7160 (21 шт., 63,5 × 38,1 мм).** Боковые поля L7166 — 4,65 мм; некоторые принтеры не печатают ближе 5 мм к краю — у края наклейки тогда пропадёт часть пустого поля, содержимое (поля наклейки 5 мм) не страдает. Другие листы — поправить числа в `lib/labels.ts`, тесты проверят, что всё влезает.
- **`lean-qr` (2.7.4) только там, где рисуется QR:** на странице печати — в клиентском чанке (~3 КБ gzip), превью на странице коробки строится на сервере (`BoxQrPreview`) и в клиентский JS не попадает. Коррекция ошибок — M.
- **Проверка печати — `page.pdf({ preferCSSPageSize: true })`:** число страниц и текст на каждой (pdf.js), плюс геометрия в `emulateMedia('print')`: каждая наклейка внутри своего листа. QR с наклейки декодируется ZXing из скриншота.
- **ZXing-js не находит крупный QR:** QR находится, только если модуль в переданной картинке не больше ~4 px; поднесённая близко наклейка даёт 8–20 px, и ZXing молчит (проверено на синтетике и размытии). Поэтому в режиме QR сканер (`components/BarcodeScanner.tsx`) сам рисует кадр в canvas и по очереди пробует размеры ×1, ½, ⅓, ¼. Встроенный `BarcodeDetector` (Android Chrome) этим не страдает. Режим штрихкода работает через `decodeFromStream`, как в 4b.

## Интерфейс: кнопки и плитки (правки после первой проверки)

- **Роль кнопки задаёт цвет, и набор один — `components/ui.ts`** (таблица в `docs/BRAND.md`, «Кнопки»). Новая кнопка берёт готовый класс; своих `bg-navy` / `bg-accent` в компонентах не писать, иначе владелец снова увидит россыпь одинаковых синих. Исключение — иконка «поиск» у строки поиска.
- **`<button>` с `display: flex` не растягивается на ширину контейнера** (в отличие от `div`): в липком футере формы кнопка была узкой слева. Футерным классам (`formSubmitClass`, `formPrimarySubmitClass`) добавлено `w-full lg:w-auto` (разные варианты, порядок в CSS не мешает).
- **Сетка отсеков — `grid-template-columns` в `style`, а не Tailwind-класс:** число колонок зависит от данных, а динамически собранный класс (`grid-cols-${n}`) Tailwind не увидит. Колонок столько же, сколько отсеков, но не больше 4 (`compartmentColumns`), остальные уходят на новую строку той же ширины.
- **Форма «+ Отсек» складывается после добавления за счёт `key={число отсеков}`** в `BoxDetail`: Server Action делает `redirect` на ту же страницу, и без смены ключа клиентское состояние «раскрыто» осталось бы. Ошибка (например, дубль кода) ключ не меняет — форма остаётся открытой с введённым кодом.
- **«Мои коробки» на главной — один запрос к `boxes`** с вложенными `locations(name, sort_order)` и `compartments(packs(count))` (`getHomeBoxes`): упаковки не скачиваются, считает база. Если количество упаковок на плитке вдруг станет 0 при непустой коробке, первым делом проверить, что PostgREST отдаёт вложенный `count`.
- **Чип срока не опирается только на цвет:** для «истекает» и «просрочено» в нём есть скрытый от глаз текст (`sr-only`) для скринридера.
- **`next dev` по адресу `127.0.0.1` не гидратирует страницу** (блокирует dev-ресурсы с чужого origin, WebSocket HMR отваливается), клиентские кнопки молчат. Для проверок в браузере открывать `http://localhost:…`. Заодно `next dev` создаёт в корне `AGENTS.md` — не коммитить, удалить.

## Сроки, покупки, письмо (Фаза 6)

- **Правило «30 дней» одно — `expiryStatus` / `SOON_DAYS` в `lib/dates.ts`.** Группы экрана «Сроки» (`lib/expiry/group.ts`), значок в меню и письмо берут оттуда границу (`attentionHorizon`) и передают её в SQL параметром (`nav_counts(p_expiry_until)`, `weekly_expiry_digest(p_secret, p_days)`): в самом SQL числа 30 нет, кроме значения по умолчанию. Дата «сегодня» — серверная, UTC (`todayIso`), так же считает `now() at time zone 'utc'` в функциях. «Годен до 12/2026» хранится как 31.12.2026.
- **Один незакрытый пункт на препарат — частичный уникальный индекс** `shopping_items (medication_id) where bought_at is null and medication_id is not null`. Двойное нажатие «В покупки» или нажатие вторым человеком даёт `23505`, приложение считает это «уже в списке» (`insertOutcome`), а не ошибкой. PostgREST `upsert` с частичным индексом не использовать. Вернуть купленное (`Вернуть в список`), пока тот же препарат добавлен заново, тоже даёт `23505` — это отдельное сообщение.
- **Кто и когда — из JWT, а не из запроса:** триггер `shopping_items_stamp` (SECURITY INVOKER) проставляет `created_by` / `bought_by` из `auth.jwt()` и не даёт переписать `created_*` и `bought_at` уже купленного. Приложение шлёт только `bought_at`.
- **Название пункта «В покупки» берётся из базы по `medication_id`, не из формы** (`addToShopping`).
- **У cron нет сессии, `service_role` в приложении нет — письмо читает данные через `security definer` функции с секретом.** Секрет — в приватной таблице `public.digest_config` (RLS без политик, без `GRANT`), вносится руками (`docs/SETUP-SUPABASE.md`, 1.5), совпадает с `CRON_SECRET`. Неверный секрет → пусто **без пояснений**, поэтому «нечего слать» и «секрет не совпал» в логе выглядят одинаково (в логе есть подсказка). `EXECUTE` на эти функции только у `anon`: ключ публичный, защита — секрет; секрет не логировать и не класть в репозиторий.
- **Письмо — по понедельникам (UTC) из существующего cron, второго cron нет.** Vercel Hobby запускает cron раз в сутки с плавающим временем в пределах часа; «один раз в неделю» держится на двух условиях: понедельник (UTC) и `last_sent_on` не моложе 6 дней (`lib/digest/schedule.ts`). Отметка ставится **после** успешной отправки (сбой Resend → в следующий запуск повтор); ещё есть `Idempotency-Key` Resend на сутки. `?force=1` (только с верным `CRON_SECRET`) пропускает оба условия и неделю отправленной не помечает.
- **Resend без своего домена доставляет только владельцу аккаунта Resend**, отправитель только `onboarding@resend.dev`; остальные адреса отклоняются `403`. Нужны `RESEND_API_KEY`, `MAIL_FROM`, `NOTIFY_EMAILS` — всех трёх нет → письмо тихо пропускается, cron отвечает ok (`digest: skipped, not_configured (set: …)`, в логе только **имена** переменных).
- **Значки в меню — одна функция `nav_counts` и `cache()` на запрос** (`lib/nav-counts.ts`): боковое меню (layout приложения) и нижнее (layout вкладок) делят один вызов. Любая ошибка (например, не применена 0006) → «без значков», а не сломанная страница. Значки обновляются после действий (`revalidatePath("/", "layout")`) и при обычной загрузке страницы; при переходах между вкладками без действий layout не перерисовывается.
- **HTML-письмо: имена препаратов экранируются** (`escapeHtml`), значения цветов — hex-токены из BRAND (письмо не читает CSS-переменные).
- **«Выбросил» — это существующее `deletePack`** с полем `returnTo=/expiry` (белый список в `deletePackDestination`): остаётся на экране «Сроки», а не уходит на карточку препарата.
- **Тесты cron-роута и письма — заглушка Resend** (`RESEND_API_URL`, только для тестов, в Vercel не задавать). `NEXT_PUBLIC_SUPABASE_PUBLISHABLE_KEY` заглушки Auth должен быть валидным JWT роли `anon`, иначе PostgREST отвечает на `ping` ошибкой и cron — `502 ping_failed`.

# PROMPTS — Local Pharm

Готовые промпты для Claude Code. Отдавать целиком, по одному. Между промптами владелец коммитит результат предыдущего.

Общий режим текущей сессии: максимум готового кода, ручную проверку владелец откладывает. Проверки КК остаются обязательными: `tsc`, `lint`, `build`, юнит-тесты для чистой логики. Всё, что нельзя проверить без Vercel, Supabase или телефона, КК записывает в CHANGELOG в раздел «Открыто: проверить владельцу».

## ПРОМПТ 2 — Фаза 1: вход, БД, защита

```
ЗАДАЧА: вход через Google (Supabase Auth), схема БД с RLS и белым списком, ежедневный keep-alive Cron.

КОНТЕКСТ: docs/PLAN.md, Фаза 1. Проект Supabase создан, провайдер Google подключён. Настройки проекта Supabase: Data API включён, «Enable RLS on new tables automatically» включено, «Grant API access to new tables automatically» ВЫКЛЮЧЕНО. Значит любая новая таблица недоступна через API, пока в миграции нет явных GRANT. Репозиторий публичный: никаких email, ключей, project ref в коде, миграциях и доках.

ЧТО СДЕЛАТЬ:
1. Зависимости: @supabase/supabase-js и @supabase/ssr, точные версии.
2. Переменные окружения (только имена): NEXT_PUBLIC_SUPABASE_URL, NEXT_PUBLIC_SUPABASE_PUBLISHABLE_KEY, CRON_SECRET. Обнови .env.example. Сборка обязана проходить без этих переменных; если их нет, приложение показывает понятную страницу «Не настроено», а не падает.
3. Миграция supabase/migrations/0001_init.sql, один файл, который владелец целиком вставит в SQL Editor Supabase. Таблицы по модели из README (Data Model): categories, locations (это зоны), boxes (с уникальным qr_token uuid), compartments (уникальный code внутри коробки), medications (source: local | amdm | openfda | manual), packs, allowed_emails (email в нижнем регистре, первичный ключ). Отклонения от модели отметь в отчёте.
4. Начальные данные в миграции: 9 категорий из README и 3 зоны (Быстрый доступ, Основной склад, В дорогу), с on conflict do nothing.
5. Защита:
   - функция public.is_allowed() (security definer, пустой search_path): true, если email из JWT в нижнем регистре есть в allowed_emails;
   - RLS включён на ВСЕХ таблицах;
   - на таблицах приложения политики для роли authenticated, using и with check через is_allowed(); для anon ничего;
   - явные GRANT select/insert/update/delete на таблицы приложения для authenticated, GRANT execute на is_allowed для authenticated;
   - allowed_emails: RLS включён, политик нет, прав для anon и authenticated нет (читает только is_allowed).
6. Функция public.ping() возвращает true, execute для anon и authenticated (нужна для keep-alive).
7. Вход: страница /login по docs/mockups/Main-v3.dc.html, кнопка «Войти через Google» (signInWithOAuth), /auth/callback обменивает code на сессию. Защита маршрутов через middleware/proxy (используй соглашение установленной версии Next.js): без сессии редирект на /login. Если email не в белом списке: выйти из сессии и показать страницу /no-access с понятным текстом. Главная после входа: заглушка с email вошедшего и кнопкой «Выйти».
8. Cron: /api/cron/keepalive вызывает supabase.rpc('ping'), требует заголовок Authorization: Bearer CRON_SECRET (если секрета нет — отказ). vercel.json: расписание раз в сутки. Service role key в приложении не использовать никогда.
9. Файл docs/SETUP-SUPABASE.md: что владелец делает руками (шаги ниже в отчёте), без секретов и без email. Для белого списка дай шаблон SQL с плейсхолдером: insert into public.allowed_emails (email) values (lower('<EMAIL>'));

ЧТО НЕ ТРОГАТЬ: docs/STATE.md, README*.md, docs/mockups/, экраны Фаз 2–3, service worker.

ПРАВИЛА: CLAUDE.md, GOTCHAS.md. Git только владелец. Дизайн по токенам.

ПРОВЕРКА: tsc, lint, build без ошибок и без переменных окружения. Юнит-тесты для чистой логики (например, проверка заголовка Cron). Если в окружении есть PostgreSQL, прогони миграцию во временной БД; если нет, перечитай SQL глазами и отметь это в «не проверено».

ОТЧЁТ: изменённые файлы; точный список шагов владельца: (а) вставить миграцию в SQL Editor, (б) добавить email в allowed_emails, (в) внести переменные в Vercel и сделать Redeploy, (г) Supabase → Authentication → URL Configuration: Site URL = домен Vercel, Redirect URLs = домен Vercel/** и http://localhost:3000/**; риски и хвосты. Ритуал завершения. Не коммитить.
```
